# Glossary for terms related to the build, test and deployment system

* The terms in this glossary MUST be used consistently throughout requirements, architecture, design, implementation, and documentation.
* New architectural components SHOULD receive an explicit name and glossary definition before becoming established terminology.
* Existing terms SHOULD NOT be reused for different concepts.

---

| Term                             | Definition                                                                                                                                                                                                                                                                                                               |
| -------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| **Artifact Module Path**         | A module's physical path in a non-bundled artifact.                                                                                                                                                                                                                                                                      |
| **Artifact Structure**           | The file/directory layout produced for a build type. Development and Test preserve module structure; Release bundles by default.                                                                                                                                                                                         |
| **Assertion API**                | The defined assertion set: assertTrue, assertFalse, assertEquals, assertNotEquals, assertNil, assertThrows, assertDeepEquals, and assertDelta.                                                                                                                                                                           |
| **Assertion**                    | A test operation verifying an expected condition and failing the test when the condition is not satisfied.                                                                                                                                                                                                               |
| **Build Artifact**               | The logical output produced by building one target. An artifact MAY contain multiple files.                                                                                                                                                                                                                              |
| **Build Configuration**          | The configuration describing a project's build targets, dependencies, groups and other build related behavior. The build config is a file named `build_config.yaml` placed inside the root of a repository, category, or project/library, or in sidecar form for small packages.                                         |
| **Build Group**                  | A named selection of build targets that can be built together. A build target can have multiple groups.                                                                                                                                                                                                                  |
| **Build Infrastructure**         | Tools and supporting scripts used for dependency resolution, building, testing, documentation, installation, and related operations.                                                                                                                                                                                     |
| **Build Pipeline**               | The ordered processing stages used to transform source code into a build artifact.                                                                                                                                                                                                                                       |
| **Build Target**                 | A user-defined configuration describing one independently buildable artifact. A build target always produces one artifact. Build target describes *what* is built.                                                                                                                                                       |
| **Build Type**                   | A predefined mode controlling how a build target is processed. The build types are Development, Test, and Release. Build type describes *how* it is built.                                                                                                                                                               |
| **Build-Type-Level Dependency**  | A dependency declared for a specific build type and available only while building that type.                                                                                                                                                                                                                             |
| **Bundled Artifact**             | An artifact in which statically included modules are combined into a single Lua file. Release artifacts are bundled by default.                                                                                                                                                                                          |
| **Bundling**                     | Combining statically resolved source modules into a single artifact file.                                                                                                                                                                                                                                                |
| **Source Code Category**         | The source code is divided into three distinct categories: `projects/` contains runnable applications/ services that can be released as an artifact; `libraries/` are reusable modules that can be included in projects; `external/` are libraries form third parties, usually containing license and source information. |
| **Category Configuration**       | A configuration file located at a category root (e.g., `/projects/build_config.yaml`, `/libraries/build_config.yaml`, `/external/build_config.yaml`) that applies category-wide defaults.                                                                                                                                |
| **Dependency Deduplication**     | Ensuring a dependency used through multiple paths is included only once in an artifact.                                                                                                                                                                                                                                  |
| **Dependency Graph**             | The directed graph describing dependency relationships between modules or libraries for a concrete project or library.                                                                                                                                                                                                   |
| **Dependency Resolver**          | The build-system component responsible for determining the dependency graph from an entry point and the dependencies available to the build.                                                                                                                                                                             |
| **Dependency Scope**             | The configuration scope in which a dependency is available. Target-level dependencies apply to all build types; build-type-level dependencies apply only to that build type. Dependency scope describes where/when a dependency is available.                                                                            |
| **Dependency Type**              | The classification determining how a dependency participates in building and deployment. The dependency types are static and dynamic. Dependency type describes *how* it is resolved and included.                                                                                                                       |
| **Dependency Validation**        | Validation of dependency declarations and resolved dependency relationships, including reporting declared-but-unused and unresolved dependencies.                                                                                                                                                                        |
| **Dependency**                   | A component required by another component for building and/or execution.                                                                                                                                                                                                                                                 |
| **Development Artifact**         | A Development artifact preserves the complete module/file structure and is neither bundled nor minified.                                                                                                                                                                                                                 |
| **Disabled Test**                | A test case or complete test suite whose name begins with `DISABLED_`; it is discovered but skipped.                                                                                                                                                                                                                     |
| **Dynamic Dependency**           | A dependency whose module identity cannot be determined statically and is resolved at runtime. It is not bundled into the main artifact and is expected to be built and made available separately.                                                                                                                       |
| **Entry Point**                  | The source file from which the project can be run (usually called init or main). The entry point also defines where static dependency resolution starts for a build type. An entry point can be defined on a build target or build type level.                                                                           |
| **Environment Setup**            | Test-runner lifecycle logic executed before test-suite execution.                                                                                                                                                                                                                                                        |
| **Environment Teardown**         | Test-runner lifecycle logic executed after test-suite execution.                                                                                                                                                                                                                                                         |
| **External Library Search Path** | A configured repository path used to locate external modules (defaults to `external/`).                                                                                                                                                                                                                                  |
| **External Library**             | Reusable Lua source code that can be used as a dependency by projects or other libraries. Shared libraries live below `libraries/`.                                                                                                                                                                                      |
| **External Module**              | A module belonging to external source code and normally addressed using the `external.` prefix.                                                                                                                                                                                                                          |
| **FAIL**                         | A test case that failed due to an assertion, execution error, or applicable lifecycle failure.                                                                                                                                                                                                                           |
| **FILES Manifest**               | A generated list in the artifact's metadata that maps each artifact-relative file path to its SHA-256 checksum, allowing individual file verification during installation.                                                                                                                                               |
| **Fixture Isolation**            | Each test suite receives a fresh fixture object, preventing fixture state from being shared between suites.                                                                                                                                                                                                              |
| **Inheritance List Reset**       | A configuration list-merging mechanism (specifically using `mode: clear` and `mode: replace`) that allows a child configuration to clear or replace inherited list values instead of appending them.                                                                                                                     |
| **Internal Module**              | An implementation module that MUST NOT be part of a library's public API.                                                                                                                                                                                                                                                |
| **Library Module**               | A module belonging to a shared library and normally addressed using the `lib.` prefix.                                                                                                                                                                                                                                   |
| **Library Search Path**          | A configured repository path used to locate shared library modules (defaults to `libraries/`).                                                                                                                                                                                                                           |
| **Library**                      | A software module that contains a collection of pre-written, reusable code that developers can use to perform common tasks. A library cannot run on its own and MUST be included inside a project to perform its functions. Shared libraries live below `libraries/`.                                                    |
| **Minification**                 | Reducing Lua source size by removing unnecessary source representation such as comments and formatting.                                                                                                                                                                                                                  |
| **Module Mapping**               | The mapping between repository source paths, module names, and artifact paths.                                                                                                                                                                                                                                           |
| **Module Name**                  | The logical name used by Lua `require()` statements. It is derived from the path relative to the applicable source root, with path separators replaced by dots and `.lua` removed.                                                                                                                                       |
| **Module Prefix**                | A configurable prefix used to distinguish module categories. Default prefixes are `lib.` for shared libraries and `external.` for external source code.                                                                                                                                                                  |
| **Module Resolution**            | Process of converting module names into repository module paths and artifact paths using a module mapping.                                                                                                                                                                                                               |
| **Package**                      | A package is a bundled collection of source files. A package can be a library, external library or a project.                                                                                                                                                                                                            |
| **Package Configuration**        | The configuration file at a package root (`build_config.yaml` for large packages) or the sidecar configuration file (`<name>.build_config.yaml` for small packages) that declares dependencies and preserved files.                                                                                                      |
| **PASS**                         | A test case whose execution and applicable lifecycle operations completed successfully.                                                                                                                                                                                                                                  |
| **Plugin Registry**              | A list or catalog describing plugins available to a project.                                                                                                                                                                                                                                                             |
| **Plugin**                       | An independently buildable, runtime-discoverable component that extends an application without being bundled into its main artifact.                                                                                                                                                                                     |
| **Preserved File**               | A source file deliberately excluded from bundling and minification. It retains its content and relative directory structure and is copied to the artifact.                                                                                                                                                               |
| **Project Module**               | A module belonging directly to a project and using no special prefix by default.                                                                                                                                                                                                                                         |
| **Project Test Runner**          | A runner that executes the tests of a single project.                                                                                                                                                                                                                                                                    |
| **Project Version**              | The version associated with a project and primarily used by release/install/update mechanisms. It is not a dependency version constraint.                                                                                                                                                                                |
| **Project**                      | A logical unit of source code and build configuration within the repository. A project may represent an application, plugin, service or another independently managed component. Projects live below `projects/`.                                                                                                        |
| **Protected Call**               | Isolated execution around test/lifecycle/runner/listener calls so an error does not crash the complete test run.                                                                                                                                                                                                         |
| **Public Interface**             | The module entry point intended for consumers of a larger library or module. Larger libraries are recommended to expose an `init.lua` public interface.                                                                                                                                                                  |
| **Release Artifact**             | A Release artifact is bundled and minified by default into a single Lua file, except for explicitly preserved files.                                                                                                                                                                                                     |
| **Repository Configuration**     | The configuration file located at the repository root (`/build_config.yaml`), providing repository-wide default settings, prefixes, search paths, and the global `artifact_base_url`.                                                                                                                                    |
| **Repository Module Path**       | A module's physical source path relative to its source root.                                                                                                                                                                                                                                                             |
| **Repository Test Runner**       | A higher-level runner that selects projects with a Test build type and executes their tests.                                                                                                                                                                                                                             |
| **Repository**                   | The complete source repository containing projects, shared libraries, external source code, documentation, build configuration, and build infrastructure.                                                                                                                                                                |
| **Require Path**                 | The module name supplied to a Lua `require()` call.                                                                                                                                                                                                                                                                      |
| **Runner Isolation**             | Each project is executed using a fresh test-runner instance.                                                                                                                                                                                                                                                             |
| **Shuffle Mode**                 | Test-runner mode that randomizes test execution order.                                                                                                                                                                                                                                                                   |
| **Shuffle Seed**                 | The explicitly reported random seed used by Shuffle Mode, allowing a randomized run to be reproduced.                                                                                                                                                                                                                    |
| **Sidecar Configuration**        | A configuration file named `<name>.build_config.yaml` placed alongside a small single-file library or external package (`<name>.lua`) to declare its static dependencies.                                                                                                                                                |
| **SKIPPED**                      | A deliberately disabled test case that was not executed.                                                                                                                                                                                                                                                                 |
| **Source Revision**              | The repository git revision from which a build artifact was generated.                                                                                                                                                                                                                                                   |
| **Source Root**                  | The directory from which module names are derived. For projects this is normally `src/`.                                                                                                                                                                                                                                 |
| **Static Dependency**            | A dependency whose module identity can be determined during build-time dependency resolution. It is included in the resulting artifact according to the artifact's build rules.                                                                                                                                          |
| **Target Identity**              | The stable logical identifier of a build target, represented as `<project>/<target>`.                                                                                                                                                                                                                                    |
| **Target-Level Dependency**      | A dependency declared for a build target and therefore available to all of its build types.                                                                                                                                                                                                                              |
| **Test Artifact**                | A Test artifact preserves the complete module/file structure and is neither bundled nor minified, so source locations remain useful for debugging.                                                                                                                                                                       |
| **Test Case**                    | A single test method in a test suite. Test methods are identified by the `test_` prefix.                                                                                                                                                                                                                                 |
| **Test Discovery**               | Automatic discovery of test suites and test cases without explicit registration.                                                                                                                                                                                                                                         |
| **Test Environment**             | A class inheriting from the `TestEnvironment` class which can contain a test entry point, environment setup and teardown methods.                                                                                                                                                                                        |
| **Test Environment Setup**       | Environment setup is executed once before the first test suite.                                                                                                                                                                                                                                                          |
| **Test Environment Teardown**    | Environment teardown is executed once after the last test suite.                                                                                                                                                                                                                                                         |
| **Test Fixture**                 | State shared by the test cases of one test suite. Class members of the suite instance form the fixture.                                                                                                                                                                                                                  |
| **Test Listener**                | A callback registered with the runner to observe test lifecycle and execution events.                                                                                                                                                                                                                                    |
| **Test Prefix**                  | A logical prefix (default `test.`) prepended to test modules to distinguish them from production code.                                                                                                                                                                                                                   |
| **Test Result**                  | One of PASS, FAIL, or SKIPPED.                                                                                                                                                                                                                                                                                           |
| **Test Runner**                  | The component that initializes the test environment, discovers test suites, executes them, and reports results.                                                                                                                                                                                                          |
| **Test Setup**                   | `setup()`, executed before every test case.                                                                                                                                                                                                                                                                              |
| **Test Suite Setup**             | `setupTestSuite()`, executed before the first test case in a suite.                                                                                                                                                                                                                                                      |
| **Test Suite Teardown**          | `teardownTestSuite()`, executed after the last test case in a suite.                                                                                                                                                                                                                                                     |
| **Test Suite**                   | A class containing one or more test cases and inheriting from the generic test-suite class.                                                                                                                                                                                                                              |
| **Test System**                  | The component responsible for discovering, executing, and reporting automated Lua tests.                                                                                                                                                                                                                                 |
| **Test Teardown**                | `teardown()`, executed after every test case.                                                                                                                                                                                                                                                                            |
| **Unbundled Artifact**           | An artifact in which modules remain separate files. Development and Test artifacts are unbundled.                                                                                                                                                                                                                        |
